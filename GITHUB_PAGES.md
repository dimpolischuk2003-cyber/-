# Як показати сайт на GitHub Pages

Pages — це безкоштовний хостинг просто з репозиторію. Підходить, щоб подивитися сайт
самому й показати команді. **Заявки з форми в цьому режимі не відправляються нікуди** —
для робочого сайту з лідами потрібен Vercel, про це в кінці файлу.

---

## Варіант А — через сайт GitHub, без командного рядка

### 1. Створити репозиторій
1. Зайдіть на [github.com](https://github.com) → кнопка **+** угорі справа → **New repository**.
2. **Repository name** — наприклад `vseodent-site`.
3. Виберіть **Public**. На безкоштовному акаунті Pages працює тільки з публічними репозиторіями.
4. Нічого не позначайте («Add a README», «.gitignore» — залиште порожніми).
5. **Create repository**.

### 2. Завантажити файли
1. На сторінці репозиторію натисніть **uploading an existing file**
   (посилання в тексті посеред екрана).
2. Розпакуйте архів у себе на компʼютері.
3. Перетягніть у вікно браузера **вміст папки**, а не саму папку:
   `index.html`, `course.html`, `README.md`, `FEEDBACK.md`, `vercel.json`,
   а також папки `assets` і `api`.
4. Унизу натисніть **Commit changes**.

> **Важливо про `.nojekyll`**
> У архіві є прихований файл `.nojekyll` — без нього GitHub може не віддавати деякі файли.
> Через перетягування приховані файли часто не завантажуються. Якщо його немає в репозиторії:
> **Add file → Create new file** → у полі назви впишіть `.nojekyll` → залиште вміст порожнім →
> **Commit changes**.

### 3. Увімкнути Pages
1. У репозиторії відкрийте вкладку **Settings** (угорі).
2. Ліворуч у меню — **Pages**.
3. У блоці **Build and deployment**:
   - **Source** → `Deploy from a branch`
   - **Branch** → `main`, папка → `/ (root)`
4. **Save**.

### 4. Дочекатися і відкрити
Перший деплой іде 1–3 хвилини. Оновіть сторінку Settings → Pages — угорі зʼявиться адреса:

```
https://ВАШ-ЛОГІН.github.io/vseodent-site/
```

Готово. Сторінки курсів відкриваються так:
`https://ВАШ-ЛОГІН.github.io/vseodent-site/course.html?slug=endo-lviv-2026-10-17`

## Варіант Б — через командний рядок

```bash
cd шлях/до/розпакованої/папки

git init
git add -A
git commit -m "VSEODENT site"
git branch -M main
git remote add origin https://github.com/ВАШ-ЛОГІН/vseodent-site.git
git push -u origin main
```

Далі — крок 3 з варіанта А (увімкнути Pages у Settings).

---

## Як оновлювати сайт далі

**Через браузер:** відкрийте потрібний файл у репозиторії → олівець (Edit) → правте → **Commit changes**.
Сайт оновиться сам за хвилину-дві.

Найчастіше вам знадобиться файл `assets/js/data.js` — там усі курси, спікери й контакти.
Щоб додати нову дату, достатньо дописати один рядок (приклад у `README.md`).

**Через командний рядок:**
```bash
git add -A
git commit -m "оновив дати"
git push
```

## Що працює і що не працює на Pages

| | Pages (прев'ю) | Vercel (робочий сайт) |
|---|---|---|
| Сайт відкривається | ✅ | ✅ |
| Розклад, фільтри, сторінки курсів | ✅ | ✅ |
| Форма відкривається і проходиться | ✅ | ✅ |
| Заявка долітає в CRM | ❌ | ✅ |
| Гарні адреси `/kurs/назва` | ❌ | ✅ |
| Свій домен | ✅ | ✅ |

У прев'ю-режимі внизу зліва видно сіру позначку **«Прев'ю · заявки не відправляються»**,
щоб тестову заявку не переплутали зі справжньою. Дані заповненої форми можна подивитися
в консолі браузера: `F12` → вкладка **Console**.

## Часті проблеми

**Відкривається порожня сторінка або немає стилів.**
Найімовірніше немає файлу `.nojekyll`. Створіть його в корені репозиторію (див. крок 2).

**Помилка 404.**
Перевірте, що `index.html` лежить у корені репозиторію, а не всередині ще однієї папки.
Якщо в репозиторії ви бачите папку `vseodent`, а вже в ній `index.html` — це не так.
Або перезавантажте файли правильно, або в Settings → Pages вкажіть папку `/docs`
і перейменуйте свою папку на `docs`.

**Зміни не зʼявляються.**
Деплой іде до 3 хвилин. Після цього оновіть сторінку з `Ctrl+Shift+R` (Windows)
або `Cmd+Shift+R` (Mac) — браузер міг закешувати стару версію.

**Сайт відкривається без картинок.**
Перевірте, що папка `assets` завантажилась цілком, разом з підпапками
`css`, `js` та `images`.

## Коли переходити на Vercel

Pages потрібен, щоб подивитися й погодити сайт. Для реклами потрібен Vercel — там
працює прийом заявок і гарні адреси сторінок.

1. [vercel.com](https://vercel.com) → увійти через GitHub.
2. **Add New → Project** → вибрати той самий репозиторій `vseodent-site`.
3. Нічого не налаштовувати, просто **Deploy**.
4. Після деплою: **Settings → Environment Variables** → додати `LEAD_WEBHOOK_URL`
   зі значенням адреси вашого n8n / Make / CRM.
5. У файлі `assets/js/data.js` знайдіть `demoMode: 'auto'` — залиште як є.
   На Vercel заявки почнуть відправлятися автоматично, позначка «Прев'ю» зникне.

Один і той самий репозиторій може одночасно жити і на Pages, і на Vercel.
Зручно: Pages — для узгодження, Vercel — для реклами.
